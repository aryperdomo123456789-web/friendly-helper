# Instruções de Deploy para Ubuntu 22.04 + aaPanel

Siga estes passos via SSH no seu servidor para colocar o projeto no ar na porta 6873:

1. **Acesse o diretório do projeto:**
   cd /www/wwwroot/stream.mago-bot.com

2. **Instale as dependências (certifique-se de ter Node.js 20+ instalado):**
   npm install --frozen-lockfile
   # ou
   bun install

3. **Gere o build de produção para Node.js:**
   # Este comando cria a pasta .output/
   npm run build:node

4. **Inicie com o PM2 usando o arquivo de configuração fornecido:**
   # Se não tiver o PM2: npm install -g pm2
   pm2 start deploy/ecosystem.config.cjs
   pm2 save

5. **Configuração do Nginx no aaPanel:**
   - Vá em "Website" -> "stream.mago-bot.com" -> "Configuration" -> "Reverse Proxy".
   - Clique em "Add reverse proxy".
   - Proxy Name: stream-proxy
   - Target URL: http://127.0.0.1:6873
   - Sent Domain: $host
   - Ou se preferir editar o arquivo de configuração manualmente, use o modelo em `deploy/nginx.conf`.

6. **Readiness e verificação:**
   - Depois de um reload, não use um atraso fixo curto como único check. Execute o readiness com polling:
     `node scripts/check-release-readiness.mjs 60000 2000`
   - O check valida a aplicação principal em `127.0.0.1:6873/`, player em `/healthz`, payments em `/healthz` e os quatro processos no PM2.
   - Verifique os logs do PM2 sem imprimir `.env`: `pm2 logs stream-mago-bot --lines 100`
   - Teste o acesso via HTTPS: `curl -k -I https://stream.mago-bot.com/`

7. **Rollback:**
   - Preserve o `.output` anterior com nome versionado antes da troca atômica.
   - Em caso de falha do readiness, restaure o diretório `.output` anterior e recarregue individualmente `stream-mago-bot`, `stream-mago-bot-player`, `stream-mago-bot-payments` e `stream-mago-bot-worker`.
   - Não use `git reset --hard`, force push, exclusão de histórico ou remoção de `.env`, `storage`, `.storage`, playlists e logs.

DICA: As portas internas devem permanecer ligadas a `127.0.0.1`; o acesso público deve passar pelo Nginx/HTTPS. Não abra 6873, 6874 ou 6875 diretamente no firewall sem necessidade operacional.
